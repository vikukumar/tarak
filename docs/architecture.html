Cluster & Runtime Architecture

Tarak is engineered from first principles in Go as a zero-dependency, ultra-low overhead container orchestration platform. Explore the interactive topology diagrams below.

Topology 01

1. Control Plane & Multi-Node Cluster Topology

Zero-etcd • Inbuilt BoltDB

Tarak separates the control plane into a high-performance API server daemon (tarakd) and worker agents (taraks), or runs unified inside a single self-contained binary (tarak).

Deterministic Scheduler

Sub-5ms placement algorithm evaluating node memory pressure, CPU allocation, and port bindings.

Embedded BoltDB Store

Eliminates heavy etcd clusters. Single-file transactional database with monotonic revision locks.

Zero-Trust WireGuard Mesh

Automatic point-to-point WireGuard and Tailscale overlay for cross-cloud and edge nodes.

Topology 02

2. Tarak Container Runtime (TCR) Engine

Zero-WSL / Native OS Isolation

TCR pulls OCI images directly from registries (Docker Hub, GHCR, Quay), unpacks filesystem layers, and spawns isolated container sandboxes using native OS process primitives without requiring Docker or containerd. 

sequenceDiagram
    autonumber
    participant CLI as tarakctl / API
    participant Engine as TCR Runtime Engine
    participant Reg as OCI Registry (Docker/GHCR)
    participant Layer as Layer Cache & Rootfs
    participant Sandbox as Process Sandbox
    participant Logs as Real Log Stream

    CLI->>Engine: RunPod(Spec: Image, Ports, Envs)
    Engine->>Reg: Pull Manifest & OCI Blobs
    Reg-->>Engine: Stream Compressed Tar Layers
    Engine->>Layer: Unpack Layers to rootfs/
    Engine->>Sandbox: Spawn Process (Entrypoint + Cmd)
    Note over Sandbox: Injects Envs, WorkingDir, and TCP Forwarders
    Sandbox->>Logs: Stream Process stdout/stderr
    Engine-->>CLI: Pod Status: Running (PID, IP, Ready)
Multi-Container & Init Pods

Executes sequential init containers before launching parallel application containers with shared loopback.

Interactive Terminal & Exec

Bidirectional PTY / WebSocket streaming allowing instant pseudo-terminal execution into active containers.
