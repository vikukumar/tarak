🏛️ Tarak System Architecture

An inside look at how Tarak achieves sub-second container orchestration without external dependencies.

1. Tarak Container Runtime (TCR)

TCR replaces the complex Docker/containerd/runc stack with native OS primitives:

  • OCI Layer Unpacker: Directly connects to Docker Hub / OCI registries, authenticates, streams tar layers, and extracts the container rootfs directly to local cache.
  • Process Isolation: Uses Linux kernel namespaces on Linux and native process job objects / token isolation on Windows/macOS.
  • Zero-Socket Overhead: Eliminates socket proxy latency, providing direct kernel scheduling.

2. Virtual Pod Bridge & Networking

Tarak assigns dedicated 10.244.0.0/16 subnet IPs to each pod. The internal Virtual Pod Bridge manages:

  • ClusterIP Routing: Instant in-memory L4 proxying between services and healthy pods.
  • MetalLB Emulation: Native public IP address pool allocation (192.168.x.x) without external CNI plugins.
  • Port-Forward Streaming: Bidirectional TCP multiplexing between client CLI and container endpoints.

3. High-Performance Pure-Go Control Plane

The Tarak control plane runs embedded in pure Go with BoltDB state storage:

  • Dual API Groups: Supports standard k8s.io endpoints and high-speed native tarak.io aliases.
  • Sub-Millisecond Raft & Watchers: Reactive event loops with zero polling latency.
  • Automatic PKI Bootstrap: P-256 ECDSA root CA, server certificates, and administrator client certificates generated in < 20ms.
