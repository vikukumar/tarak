⚡ Inbuilt Cloudflare & Tailscale Tunnels

Expose applications instantly to the internet or your private mesh network with zero port forwarding, automatic TLS, and native Ingress routing.

☁️ Cloudflare Tunnels (Quick & Named)

Automatically exposes Ingress routes to Cloudflare Edge. Supports instant zero-config ephemeral HTTPS URLs (*.trycloudflare.com) or custom persistent production domains (*.vikshro.in) using tunnel tokens.

🔒 Tailscale Private Mesh

Connects the Tarak cluster directly to your private Tailnet with MagicDNS (app.tailnet.ts.net). Allows teams to access internal cluster services securely from any device without public internet exposure.

1. Enabling Tunnels on the Control Plane

Start tarakd (or tarak server) with tunnel flags enabled:

# Quick Tunnel (Auto-generated public HTTPS URL)
tarakd server --cloudflare-tunnel --ingress-http-addr 0.0.0.0:8080

# Named Tunnel with custom production domain token
tarakd server --cloudflare-tunnel --cloudflare-token <YOUR_TUNNEL_TOKEN>

# Tailscale Mesh Sharing
tarakd server --tailscale --tailscale-authkey <YOUR_TS_AUTHKEY>

2. Declaring an Ingress Route

Use standard Kubernetes Ingress resources with ingressClassName: tarak-cloudflare or tarak-tailscale:

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: secure-web-ingress
  namespace: default
spec:
  ingressClassName: tarak-cloudflare
  rules:
  - host: app.vikshro.in
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web-app-svc
            port:
              number: 80

3. Inspecting Active Tunnels with tarakctl

View the live public URLs and operational status of all active tunnels:

# List active tunnels and public endpoints
tarakctl tunnel list

# Output example:
# TYPE STATUS MODE PUBLIC URL AGE
# CLOUDFLARE Active quick-tunnel https://demo-app-7fa2.trycloudflare.com 2m
# TAILSCALE Active magic-dns https://tarak-cluster.ts.net 2m
