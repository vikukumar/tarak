24/7 Production Service

🐧 Linux Background Daemon (systemd)

Auto-Restart & Zero-Downtime

To ensure Tarak runs continuously in the background across reboots on Ubuntu, Debian, RHEL, or Rocky Linux:

sudo tee /etc/systemd/system/tarak.service << 'EOF' [Unit] Description=Tarak Container Orchestrator Control Plane Documentation=https://tarak.vikshro.in/ After=network-online.target Wants=network-online.target [Service] Type=exec ExecStart=/usr/local/bin/tarak server --data-dir=/var/lib/tarak --bind-address=0.0.0.0:6443 --log-level=info Restart=always RestartSec=5s LimitNOFILE=1048576 LimitNPROC=infinity LimitCORE=infinity TasksMax=infinity KillMode=process [Install] WantedBy=multi-user.target EOF # Reload & activate background service: sudo systemctl daemon-reload sudo systemctl enable --now tarak sudo systemctl status tarak
Command 01

1. tarak init — Cluster Bootstrap & PKI Generator

Generates the ECDSA P-256 root CA, signs server/client certificates, initializes state directory, and outputs an administrator kubeconfig.

tarak init --data-dir=/var/lib/tarak --bind-address=0.0.0.0:6443 --tls-san=cluster.internal,10.0.0.1 --kubeconfig=/etc/tarak/admin.kubeconfig
Flag Default Description
--data-dir <path> ~/.tarak/data Directory to store cluster state, PKI certificates, and layer caches
--bind-address <host:port> 127.0.0.1:6443 API server advertise host address and port
--tls-san <list> localhost,127.0.0.1 Comma-separated Subject Alternative Names (SANs) for TLS certificate validation
--kubeconfig <path> ~/.tarak/config Output path for cluster administrator kubeconfig file
Command 02

2. tarak server / tarakd — Control Plane API Server

Starts the production API server, scheduler, workload controllers, BoltDB transactional store, and ingress reverse proxy.

tarak server --bind-address=0.0.0.0:6443 --ingress-http-addr=0.0.0.0:80 --cloudflare-tunnel --cpu-limit=8 --memory-limit=16Gi
Flag Default Description
--bind-address <host:port> 0.0.0.0:6443 Bind host address and port for the HTTPS API server
--ingress-http-addr <host:port> 0.0.0.0:8080 Host address and port for the HTTP Ingress reverse proxy
--data-dir <path> ~/.tarak/data Persistent data directory for BoltDB storage and layer caches
--cloudflare-tunnel false Enable zero-config Cloudflare public ingress tunnel
--cloudflare-token <token> none Cloudflare Named Tunnel token for custom domain binding
--tailscale false Enable Tailscale zero-trust private WireGuard mesh networking
--tailscale-authkey <key> none Tailscale node join authentication key
--cpu-limit <cores> 100% host Maximum CPU cores allocated to scheduled workloads
--memory-limit <bytes> 100% host Maximum RAM allocated to scheduled workloads (e.g. 16Gi)
--gpu-limit <count> all GPUs GPU devices limit allocated for container execution
--log-level <level> info Logging verbosity level: debug | info | warn | error
--shutdown-timeout <duration> 30s Graceful workload drain deadline during shutdown
Command 03

3. tarak agent / taraks — Worker Node Agent

Starts the local node execution agent, TCR container sandbox, and virtual pod bridge CNI.

taraks --server=https://192.168.1.10:6443 --token=my-secret-token --node-name=worker-01 --data-dir=/var/lib/tarak
Flag Default Description
--server <url> https://127.0.0.1:6443 Master control plane API server endpoint URL
--token <token> none Cluster mutual TLS join authentication token
--node-name <string> hostname Unique worker node identifier in the cluster
--data-dir <path> ~/.tarak/data Local container rootfs layers and overlay storage directory
--log-level <level> info Logging verbosity: debug | info | warn | error
