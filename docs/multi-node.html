🌐 Multi-Node Clustering Guide

Deploy a distributed cluster with separated Control Plane nodes and N Worker Nodes across different physical or virtual servers.

1. Architecture Overview

In a multi-node Tarak cluster, nodes have distinct specialized roles:

🖥️ Control Plane Node (tarakd)

Runs the central API Server, Raft / BoltDB state store, admission webhooks, and controller manager (Deployments, Services, MetalLB, and Pod placement).

🤖 Worker Nodes (taraks)

Runs the lightweight TCR container execution runtime, manages local container processes and rootfs caches, and streams telemetry metrics.

2. Starting the Control Plane Node

On your primary server (e.g. IP 192.168.1.100), initialize PKI and start the control plane:

# Initialize cluster PKI with the server's public/LAN IP in SANs
tarak init --bind-address 0.0.0.0:6443 --tls-san 192.168.1.100,localhost

# Start the control plane API server
tarakd server --bind-address 0.0.0.0:6443 --data-dir /var/lib/tarak

3. Joining Worker Nodes

On each worker machine (Linux, Windows, or macOS), run the dedicated worker agent:

# Start worker agent and connect to the control plane
taraks agent --server https://192.168.1.100:6443 --node-name worker-node-1

4. Inspecting Cluster Nodes & Metrics

From your administrator laptop using tarakctl:

# List all cluster nodes with OS, Arch, and status
tarakctl get nodes -o wide

# View real-time CPU & Memory utilization across nodes
tarakctl top nodes

Workloads deployed via tarakctl apply -f will automatically be scheduled and balanced across your active worker nodes!
